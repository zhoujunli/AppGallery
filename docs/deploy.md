# 部署手册：OSS 静态托管 + 云效流水线

本文档面向站主本人，描述如何把本站部署到阿里云 OSS，并通过**云效流水线**从 **Codeup 仓库**自动构建、上传。照着一步步做即可完成对外发布。

> 全站是**零构建**的静态站点：没有打包、编译步骤，上传的就是仓库里的原始文件。唯一的"构建产物"是 `versions.json`，见下文。浏览器端只 `fetch('versions.json')` 读取版本数据，**前端不调用任何 GitHub API** —— 版本数据在**构建期**由流水线拉取并写入 `versions.json`。

## 部署架构总览

```
Codeup 仓库 (feat/appgallery)
        │  触发
        ▼
云效流水线
   1. node scripts/validate-projects.mjs   # 校验 projects.js 数据
   2. node scripts/fetch-releases.mjs      # 用 GITHUB_TOKEN 拉 GitHub Releases → versions.json
   3. ossutil cp ...                        # 上传静态文件到 OSS
        │
        ▼
OSS Bucket（标准存储 + 静态网站托管）
        │  绑定
        ▼
已备案的自定义域名  https://<你的域名>/
```

## 占位符约定

文档中出现下列占位符，请替换为你自己的真实值，**不要**把它们（或任何密钥）写进仓库：

| 占位符 | 含义 |
| --- | --- |
| `<bucket>` | 你的 OSS Bucket 名称 |
| `<你的域名>` | 你**已备案**、要绑定到 OSS 的自定义域名 |

---

## 1. 建 Bucket

**在哪做：** OSS 控制台 →「Bucket 列表」→「创建 Bucket」。

**做什么：**

- **Bucket 名称**：全局唯一，例如 `appgallery-<你的标识>`。创建后不可改名。
- **地域（Region）**：选**离访客最近**的地域。访客主要在中国大陆就选华东/华北/华南等大陆地域。
  > 注意：选**中国大陆**地域的 Bucket，后面绑自定义域名时**必须使用已备案域名**（第 4 步）。
- **存储类型**：**标准存储**（Standard）。静态站点是小文件、需要随时可读，标准存储即可，不要选低频/归档。
- **读写权限**：设为**公共读**（Public Read）。本站是面向所有人开放的展示站，页面文件必须允许**匿名 GET** 读取 —— 这是站点能打开的前提，不是可选加固。
  - 若不愿在 Bucket 级别设公共读，则采用替代做法：在第 3 步关闭「阻止公共访问」后，为该 Bucket 加一条 **Bucket Policy**，授予任意来源（Principal `*`）`oss:GetObject` 权限。**二选一，但不能两个都不做。**
  - 公共读意味着任何人拿到对象 URL 都能下载该文件。如需限制，可按需配置「数据管理 → 防盗链」的 Referer 白名单。（注：安装包本来就在 GitHub Releases，本站只上传页面与 `versions.json`，公共读不引入额外暴露。）

> 若在此处无法设为公共读（选项被阻止或置灰），说明「阻止公共访问」还开着 —— 先完成第 3 步关闭它，再回来设置。两步的先后可以互换，但**必须都完成**。

**怎么验证做对了：** 创建完成后，Bucket 出现在「Bucket 列表」中，地域、存储类型与你所选一致；Bucket 读写权限为**公共读**（或稍后在权限管理里已补上授予匿名 `oss:GetObject` 的 Bucket Policy）。

---

## 2. 开静态网站托管

**在哪做：** 进入该 Bucket →「数据管理」→「静态页面」（即静态网站托管）。

**做什么：**

- 开启**静态网站托管**。
- **默认首页（Index Document）**：`index.html`
- **默认 404 页（Error Document）**：`404.html`
  - 这样访客访问不存在的路径时，看到的是**你自己的 404 页**，而不是 OSS 的默认报错页。

**怎么验证做对了：** 保存后页面显示托管已开启，且首页 / 404 页分别配置为 `index.html` / `404.html`。

> 说明：静态网站托管只负责"找到文件、渲染页面"。它不自动放开权限，因此还需要第 3 步。

---

## 3. 关掉「阻止公共访问」

**在哪做：** 进入该 Bucket →「权限管理」→「阻止公共访问」。

**做什么：**

- 关闭「**阻止公共访问**」（Block Public Access）。

**为什么必须关：**

- 阿里云 OSS 新建 Bucket 默认**开启**「阻止公共访问」。开启状态下，任何**匿名（未签名）请求一律被拒绝**，访客用浏览器直接打开你的站点时，HTML/CSS/JS 全部返回 403，页面根本无法显示。
- 静态网站托管的本质就是让访客用**匿名 GET** 请求读取页面文件。要提供这种匿名读取，关闭这道总闸是**前提之一**，但还不够。
- 关闭只是解除这道总闸，**它本身并不授予任何读权限**。对象的匿名读权限仍由第 1 步的「公共读」ACL（或你在此处补的 Bucket Policy）决定 —— 两处都做完，匿名 GET 才会真正放行；只关总闸会得到 **403 AccessDenied**。写权限则由第 6 步的 RAM 子账号单独控制，**不会**因为这里关闭而对公众放开写入。

**怎么验证做对了：** 「阻止公共访问」状态显示为**已关闭**。

**若验证不过（403 AccessDenied），按此顺序排查：**

1. 「阻止公共访问」是否已关闭；
2. Bucket 读写权限是否为**公共读**，或 Bucket Policy 是否授予了匿名 `oss:GetObject`；
3. 对象是否确实已经上传（对应第 7 步）。

---

## 4. 绑自定义域名（必须用已备案域名）

**在哪做：** 进入该 Bucket →「数据管理」→「域名管理」→「绑定域名」。

**做什么：**

- 绑定你的自定义域名：`<你的域名>`。
- 按提示到你的 DNS 服务商处，为 `<你的域名>` 添加一条 **CNAME** 记录，指向 OSS 给出的 CNAME 目标地址（形如 `<bucket>.oss-cn-<region>.aliyuncs.com`）。
- 等待 DNS 生效。

**为什么必须用已备案域名（重点）：**

- **OSS 默认域名访问 HTML 会被强制下载。** 通过 OSS 默认域名（`*.oss-cn-*.aliyuncs.com`）访问 `.html` 文件时，OSS 会在响应里加上 `Content-Disposition: attachment`，浏览器会弹出"下载"而不是渲染页面。这是 OSS 的默认安全策略，用于防止有人借 OSS 域名托管网页做钓鱼。
- 因此**不能**把默认域名当站点域名用。只有绑定**自定义域名**后，HTML 才会正常以 `text/html` 渲染。
- 而且，**中国大陆地域的 OSS 要求绑定的自定义域名必须先完成 ICP 备案**，否则绑定无法通过。所以请使用**已备案的域名**；未备案域名只能绑在**非中国大陆**地域的 Bucket 上。

**怎么验证做对了：** DNS 生效后，在浏览器地址栏直接访问 `https://<你的域名>/index.html` —— 页面应**正常渲染**，而不是提示下载文件。这一步正是"自定义域名生效"的验收点。

---

## 5. 配 HTTPS 证书

**在哪做：** 阿里云「数字证书管理服务」控制台 →「证书申请」，申请一张免费证书；再回到 OSS 「域名管理」。

**做什么：**

- 在阿里云证书服务申请**免费 DV 证书**，绑定域名 `<你的域名>`，完成域名所有权验证，等待签发。
- 回到 OSS Bucket →「域名管理」→ 找到 `<你的域名>` → **证书托管**，选择刚签发的证书并绑定。
- 在 OSS 域名设置里开启**强制 HTTPS 跳转**（如需）。

**怎么验证做对了：** 用浏览器访问 `https://<你的域名>/`，地址栏显示**锁形图标**，证书主体为你的域名，无"不安全"警告。

---

## 6. 建 RAM 子账号（只授予该 Bucket 读写权限）

**在哪做：** 阿里云「访问控制 RAM」控制台。

**做什么：**

- 新建一个 **RAM 用户**（子账号），仅用于流水线部署，**不要**用主账号 AccessKey。
- 为该子账号创建**自定义权限策略**，把可操作范围**限定到这一个 Bucket**。可直接粘贴下面这份（把 `<bucket>` 换成你的 Bucket 名）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject",
        "oss:ListObjects"
      ],
      "Resource": [
        "acs:oss:*:*:<bucket>",
        "acs:oss:*:*:<bucket>/*"
      ]
    }
  ]
}
```

  - Resource 给**两条**：bucket 本身（`oss:ListObjects` 作用在 bucket 级）与 `/*`（对象级读写）。两条都要。
  - **不要**把 Resource 写成 `*`，那等于放开该账号能访问的所有 bucket，超出本流水线所需。
- 为该子账号生成 **AccessKey ID / AccessKey Secret**。

**凭据不入库（重要）：**

- **这些值一律不入库。** AccessKey 只填进云效流水线的**密钥管理**（第 7 步），绝不写进代码、配置或提交记录。
- 同理，第 7 步用到的 `GITHUB_TOKEN` 也**只存在于流水线的密钥管理里，不写入仓库**。

**怎么验证做对了：** 该子账号在 RAM 中可见，权限策略的 Resource 只包含 `<bucket>`；AccessKey 已生成（妥善保存，Secret 通常只显示一次）。

## 7. 配云效流水线

**在哪做：** 阿里云「云效」→「流水线」，新建一条流水线，关联你的 **Codeup 仓库**。

流水线按顺序执行以下阶段。**顺序不能颠倒**：`versions.json` 是构建产物（在 `.gitignore` 里，当前仓库中并不存在），必须**先由脚本生成、再上传**。

### 阶段 A：拉代码

- 源：Codeup 仓库，分支 `feat/appgallery`（或你的发布分支）。

### 阶段 B：校验与构建

```bash
node scripts/validate-projects.mjs
node scripts/fetch-releases.mjs
```

- `validate-projects.mjs`：校验 `projects.js` 数据合法。
- `fetch-releases.mjs`（= `npm run versions`）：从**环境变量 `GITHUB_TOKEN`** 读取凭据，构建期拉取 GitHub Releases，写出 `versions.json`。
  - `GITHUB_TOKEN` 通过云效流水线的**密钥管理**注入为环境变量，**不入库**。
  - 若 `fetch-releases.mjs` 拉取失败，它会保留上一次的 `versions.json` 而不覆盖（避免把线上版本数据写坏）。
  - 注意：必须先跑完这一步，`versions.json` 才会存在，下面的上传步骤才有文件可传。

### 阶段 C：上传到 OSS

先确认构建环境里 `ossutil` 可用，执行：

```bash
ossutil --version
```

- 若输出正常，说明镜像已预装，直接进入下面的上传步骤。
- 若报命令不存在，则需要让 `ossutil` 就位：从 **OSS 官方发布包**获取与你构建环境 CPU 架构匹配的 `ossutil` 二进制，放进构建环境的 `PATH`。可在流水线里用一条一次性命令下载并赋予可执行权限后，再执行上传命令。（不同云效环境的预装情况不一，这里保守处理：**确认可用，不可用则按官方发布包安装**。）

然后配置 `ossutil` 使用第 6 步 RAM 子账号的 AccessKey（同样从**密钥管理**读取，**不入库**），执行：

```
ossutil cp index.html oss://<bucket>/
ossutil cp project.html oss://<bucket>/
ossutil cp 404.html oss://<bucket>/
ossutil cp projects.js oss://<bucket>/
ossutil cp versions.json oss://<bucket>/
ossutil cp -r assets/ oss://<bucket>/assets/
ossutil cp -r icons/ oss://<bucket>/icons/
```

> 注：`icons/` 目录在**补齐图标后才存在**（后续任务创建）。在该目录尚未创建前，这一行会因源目录缺失而报错；此时可先**跳过该行**，待目录生成后再补传。其余行不受影响。

**不要上传**以下内容（它们是仓库的工程文件，不属于站点资源）：

- `scripts/` —— 构建脚本，只在流水线里跑，不上传
- `docs/` —— 文档，不上传
- `tests/`、`.superpowers/` —— 测试与工具临时产物，不上传
- `package.json`、`.gitignore` —— 工程配置，不上传

简言之：**只上传浏览器运行所需的静态资源**（三个 HTML、`projects.js`、`versions.json`、`assets/`、`icons/`）。

**怎么验证做对了：** 流水线运行成功；回到 OSS Bucket 文件列表，能看到 `index.html`、`project.html`、`404.html`、`projects.js`、`versions.json`、`assets/`（以及存在时的 `icons/`），且**看不到** `scripts/`、`docs/`。

## 8. 触发方式

**必做：手动触发**

- 在云效流水线上配置**手动触发**：进入流水线点击"运行"，即可按当前代码部署一次。日常发布用这个即可。

**可选：GitHub release webhook 全自动**

- 若希望 GitHub 一发新版就自动部署：为 GitHub 仓库配置一个 **webhook**，在发 Release 时调用云效流水线的**触发 Webhook URL**，由云效自动启动流水线。
- 这样 GitHub Release 更新 → 流水线自动重跑 `fetch-releases.mjs` → `versions.json` 更新 → 自动上传，站点版本号随之刷新。

**怎么验证做对了：** 手动点一次"运行"能成功部署；如配置了 webhook，在 GitHub 发一次 Release，云效流水线被自动触发。

---

## 9. 回滚

出问题时，把代码改回上一个已知正常的提交，再重新部署即可：

**在哪做：** 本地/Codeup 仓库 + 云效流水线。

**做什么：**

- 定位上一个正常发布的提交（`git log`）。
- 用 `git revert <坏提交>` 生成一个反向提交（或把发布分支指回上一个正常提交）。
- 让流水线基于该提交重新运行一次（手动触发），即可用旧内容覆盖线上。

**怎么验证做对了：** 重新部署后，访问 `https://<你的域名>/` 确认页面恢复为正常版本。

> 如需更强保障，可开启 OSS 的**版本控制（Versioning）**，这样每次上传都保留历史对象，必要时可按对象版本直接回退，无需重新部署。

## 附：部署后走查清单

流水线首次部署成功后，用**手机流量**（不要用公司内网，避免缓存/CDN 干扰）访问 `https://<你的域名>/` 逐项确认：

- [ ] 首页在**浅色**与**深色**下都正常显示
- [ ] 卡片上的**版本号来自真实 GitHub Releases**，与仓库里的一致
- [ ] 点**下载**能真的下到安装包
- [ ] 随便输一个**不存在的路径**，出现的是**自己的 404 页**，不是 OSS 的默认报错页
- [ ] 浏览器直接访问 `https://<你的域名>/index.html`，页面**正常渲染**而不是提示下载（专门验证**自定义域名已生效**，见第 4 步）
